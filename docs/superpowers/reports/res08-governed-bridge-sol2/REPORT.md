- `predictive_experiment.py`: v2 experiments bind exact selected candle and
  retained revision fingerprints, discovery/protected slices, evaluation
  module versions and the unmodified RES-07 proposal contract. Translation
  retains scope, observables, support/opposition, falsification, required
  measurements and limitations. Frozen data refuses a changed source revision;
  identical data/cut/code reproduces the same experiment. Translation attempts

  verify exact hypothesis/experiment versions, cut, code/data provenance,
  rendered combination, actual retained numerical output and registered ledger
  evidence. A label cannot certify itself. PASS/FAIL requires measured,
  sufficient registered referee evidence; everything else has quantitative
  outcome UNTESTED. Results retain a canonical measured-result ID, quantitative
  evidence ID, Bank result ID, conclusion ID, limitations and next questions.
- `predictive_bridge.py`: verifies feedback before persistence, retains v2
  receipts, restores registered budget parameters with spent looks, refuses
  incompatible protected cuts and keeps changed source versions as related
  proposals. Rejected referee output is retained as refused evidence and the
  already-consumed look is charged as untestable; retry cannot evade that look.
- `predictive_bank.py`: verifies v2 attachments and exact retained next-question
  payloads during readonly replay, and returns persisted translations. Historical
  v1 records remain replayable without changing identity. A new validated result
  cannot be certified using an unbound legacy experiment.

## Exact lineage and quantitative boundary

The immutable chain is proposal `hypothesis_id`/schema -> `experiment_id`/schema
-> worker `measurement_id` and canonical measured-result ID -> registered
quantitative evidence ID (including candidate, rendered rule, budget, spent
look and referee evidence) -> Bank `result_id` -> `conclusion_id` -> limitations
and exact next-question IDs. Source provenance hash and the experiment's
source/protected fingerprints, split/cut and evaluation module versions are
bound into those receipts. No latest-data lookup is needed for Bank replay.

Registered quantitative evidence is loaded from the experiment's own bound
ledger rather than accepted from a narrative. Its retained numerical readings
must match successful worker receipts. Referee conclusions recompute the
existing dependence-aware gate, check sufficient power, exact registered
cut and LORD ceiling, and bind the actual look to its measurements. The
existing factory gate remains authoritative for candidate-to-strategy work;
RES-08 writes no StrategyVersion and grants no activation authority.

QNT-03 dependence correction/common rotation, QNT-04 protected/spent cut,
QNT-05 registered budget and QNT-06 UNTESTED semantics are preserved. Discovery
support is not referee support. Insufficient data is neither PASS nor FAIL.
Causal explanation remains UNKNOWN even after a registered expression has
quantitative support. Protocol fixtures with positive synthetic readings are
not a claim of real profitable predictive edge.
