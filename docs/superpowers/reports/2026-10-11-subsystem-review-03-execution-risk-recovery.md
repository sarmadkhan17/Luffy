## Part A — whole subsystem
**Entry chain (source contract):** kernel scan gate (`kernel.py:1186`) -> `risk.check_entry` (`risk.py`) -> `entry_authority.authorize` (second `check_entry` on authoritative equity/book, control fence, capability, venue identity, one exposure per instrument) -> `executor.open` (persisted state, exec_mode==live, version fence, locks) -> `entry_authority.submit` (durable reservation in `execution_requests` + recovery intent in one IMMEDIATE tx BEFORE `create_order`; ambiguous result stays UNKNOWN and is recovered by exact client-order-id, never replayed) -> native stop -> `add_trade` -> `recovery.finish`.
**Exits:** only `Executor.close/close_partial` (reduceOnly); TP1 via durable `partial_exit_intents`; stop ratchet places new stop before cancelling old; final close books venue fills / labelled estimate.
**Protection:** `protective.py` handles Binance algo IDs; `sweep_orphans` never strips a live symbol with no known stop.
**Reconcile/recovery:** adopt, align, ghost-close, orphan sweep, naked re-arm from venue size; ACTIVE only via Risk-gated CAS with fresh venue/protection proof.
**Connections:** Kernel is sole runtime importer; Safety consulted via `observability.safety.entry_refusal`; Portfolio imports `risk_intent`, `protection_snapshot`, `entry_authority`; Market Data via `execution_account_scope`; Learning via outcomes/booking; Journal via `core.journal` only (no `Journal.query()` writes).
**Persisted financial state:** trades; trade_accounting_bookings/legs/fills; execution_requests (UNIQUE logical/decision/client id); state_kv execution_recovery + control_events; partial_exit_intents; execution_accounting; risk_state / baseline marker / corrupt latch; control_state + macro_guard_operator_hold + intent watermark; supervisor_status; reconcile_rearm_submitted; capability/account/margin/position snapshots; panic_requested, close_requests. Only `EntryPermission` is memory-only.

### Redundancy (intentional vs. real)
Intentional defense in depth — do NOT simplify: control state read at gate/open/authorize/submit/validate; `validate` twice around the reservation commit; `entry_refusal` at three points; risk layers (kernel gate, check_entry, authorize check_entry, executor fence, submit fence, Supervisor release).
Real duplication: canonical-JSON/digest/number helpers re-implemented in ~9 modules; four capture/assess/replay modules (trade_accounting, conversion_evidence, native_exit_provenance, emergency_whole_accounting) + six CLI scripts with the same scaffold, three with scripts-only importers; two naked-position coverage standards (non-verify reconcile counts ANY stop, verify uses `protection_match`); `tests/paper_cost_evidence_fixture.py` was byte-identical to `authority_cost_fixtures.py` (now re-export); layering inversion (`entry_authority` imports dashboard/observability constants); misplaced domains (rent*, risk_intent, orchestrator/outcomes/excursion, owner-frontend tests, `portfolio_allocator_shadow.py`); obsolete: `Executor._ensure_leverage` (removed in 8d49c69) still expected by tests, `reconcile._now`, unused `_position_risk(mark)` arg.

## Confirmed defects
- **C-1 (safety, PROPOSED_ONLY):** `reconcile.flatten_all` cancels the venue stop (`reconcile.py:510-511`) BEFORE the reduce-only close is accepted (`:512`). If the close raises, the journal-open position has no venue stop, and the "retry next cycle" log is false because `kernel._drain_panic` (`kernel.py:2150-2154`) clears `panic_requested` after one call. Also sizes from journal amount, ignoring venue positions absent from the journal. Pinned by strict xfail `tests/test_reconcile.py::test_flatten_failure_keeps_the_protective_stop`. Fix needs Kernel + Safety review; not changed.
- **C-2 (IMPLEMENTED_OFFLINE):** `ControlStateMachine.can_enter()` returned True from stale in-memory ACTIVE when persisted state was invalid (contradicting `control_fence.persisted_state` fail-closed). Executor fence still refused the order, so no exposure leaked; scan gate was wrong. Tightening only.
- **C-3 (IMPLEMENTED_OFFLINE):** 63 stale test failures across 9 modules meant quantization, lot-step, provenance, naked-position and leverage guards were silently not running.
- **C-4 (TEST_ONLY):** no test covered exec_mode!=live refusal or venue endpoint switch after authorization.
