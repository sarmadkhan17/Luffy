## Actual gap and change

No implementation gap was demonstrated for the supported anomaly producer.
The missing acceptance evidence was a test through the normal entry point;
the retained research-family tests invoked `step`/`run` directly.

Added `tests/test_res01_question_producer.py` with six bounded offline checks.
Each producer invocation uses a fresh interpreter; only the data root and
wall clock are redirected, and socket connections are forbidden. Attention
events come from provenance-annotated synthetic candles through the existing
capture/Store helpers. The tests never insert a case/question or provide a
URL, replace a producer, or run Kernel/providers.

- A supported volume anomaly creates exactly one typed question through
  `main`, with exact retained source identities and scan/case hashes.
- Absent forward outcome evidence stays INCONCLUSIVE/NOT_ASSESSED.
- Restart produces zero additional work and preserves all canonical records
  and the question byte-for-byte.
- Quiet inputs, missing source and missing health produce no question;
  missing inputs retain explicit degraded reasons.
- Removing required registration context makes the automatic research pass
  refuse explicitly, with no research records written.
- A disabled producer reports disabled and creates no investigation database.

The adjacent `2026-10-06-res01-sol1-question-proof.json` pins an actual output
of this offline test, its source lineage, retained record hashes and restart
health showing zero newly attempted research. It is synthetic replay evidence,
not a live-market/runtime or rollout claim. Deployment remains opt-in.
