## Single effective lifecycle authority

The existing factory_handoff module remains the version authority, rather than adding a differently named controller. VALIDATED → SHADOW → APPROVAL_REQUIRED → APPROVED_FIRST_LIVE is bound to immutable validation, install, probation and owner-decision records. The same module now owns subsequent ACTIVE, DEGRADED, PAUSED, REACTIVATED and RETIRED governance records. An owner supplies the first allocation ceiling for the already-approved exact version; automatic governance cannot enlarge it. Activation/reactivation rechecks the exact approval, immutable cost receipts, install, validation, current capacity and unchanged Risk configuration. Stop/degrade/retire sets allocation to zero. Repeated pause/resume cycles are append-only and replayable; retirement is terminal. Changed versions have no grant and require new validation, probation and approval.

ACTIVE is a governance state, not evidence that orders were enabled. The separately enforced live-entry fence remains intact and still blocks versioned live execution. No activation action was performed or execution scope granted. This package supplies lifecycle authority within that boundary; it does not claim first-live activation.

Kernel decay is advisory until the version authority records retirement; the strategies row is then its projection. The exact-install refusal path also records retirement through that authority. The legacy genome promotion path already observes specs without changing their lifecycle. Underpowered recent data/opportunity absence remains idle under Analyst.review_deployed rather than decay.

## Prospective capture

Executor uses a transparent observer of the calls it already makes. Original arguments, results and exceptions are preserved; no additional authenticated request or credential is introduced. Kernel supplies entry reference observation time, and existing exit snapshots supply exit reference time when available. Requested size, actual submission time, immutable identity, order ID, status/partial outcome, returned fill timestamps/quantities/prices and returned fee/asset observations are captured. Ordinary and existing algo cancellation responses/errors are retained; submission timeout stays ambiguous. Fee information returned for an exact order is not an applicable account commission-rate authority.

Decision/pre-submission depth capture runs asynchronously using public GETs, one daemon worker, at most 32 pending tasks, depth 20, collection age bound 5000 ms, public timeouts/body/page bounds, a 256 MiB sidecar storage ceiling and 512 KiB per-record ceiling. These are collection bounds, not economic or model-validation constants. Actual delays are retained, including NOT_EXACT_EVENT_TIME_BOOK. Public failures, storage bounds, queue bounds and execution-evidence.STOP produce explicit blockers. No blind polling depth collector is restarted.

Paper entry freezes environment from the actual market-data endpoint plus quantity/side/market/instrument/time in immutable entry identity; current environment flags are not historical proof. Paper management records the final funding interval, and Kernel has a separate 60-second, maximum-32-open-position public funding recorder so lack of new strategy snapshots does not silently stop collection. Public event rate/time/mark receipts remain hash-replayable. Exact hypothetical notional is the frozen paper quantity times the venue event mark; missing marks, changed exposure, demo obligations and boundary timing remain unavailable. Captured funding evidence does not backfill or upgrade a finalized unknown cost receipt.

Sidecar replay binds existing intents, scoped order IDs, exact fill IDs and explicitly linked captures. It rejects hash tampering, duplicate/conflicting scoped fills and missing exact links; no time-window reconstruction is added. No minimum sample count or validated slippage/capacity model is invented.
