## Replay, recovery and deletion safety

Research consumers `predictive_receipt.snapshot` and `factory_transfer.authenticate` now use the same reader for a live bound ledger or retained Bank evidence. A restored quantitative image verifies typed rows, rowids and DDL and opens query-only in RAM. The frozen dataset restores from exact bytes and its original SHA256. Financial and recovery data in a proposed working copy refuse retirement. The original positive and negative records and complete cumulative look/budget rows remain unchanged.

The archive commits and is reread before unlink. A crash or unlink error leaves a committed recovery capsule; restart verifies each surviving file before continuing. Archive commit failure deletes no file. A changed surviving file refuses cleanup. A corrupt already-retired capsule also refuses success instead of reporting healthy retirement. No operation compacts an operational database.

Learning's duplicate/update/delete guards retain logical immutability; representation updates must resolve to exactly the old serialized text. Direct known readers and SQL JSON predicates read the verified logical views. Source chunks remain available while referenced; Learning does not garbage-collect them. Unknown views or trigger definitions refuse old-payload replacement. An incomplete outcome never becomes replay-complete through compression.

Portfolio's scan progress is stored in existing codec metadata. Immutable evaluations/checkpoints allow progress across restarts. Tail checks include arrivals after earlier scan steps; current mutable state is checked in the final writer transaction. Every candidate additionally has a reconstruction witness and unchanged compressed proof. Failed cleanup uses a savepoint and cannot roll back a valid new portfolio checkpoint. Unknown dependencies cancel that witness and advance to other work.

Existing tests that intentionally tamper with a physical Research ledger now explicitly restore their isolated test ledger from retained evidence. Missing both representations, foreign bindings, altered combinations, invalid candidates and incorrect statistical evidence still refuse. The Factory's validation/transfer and activation boundaries are unchanged.
