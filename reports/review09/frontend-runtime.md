## Connected behavior and honest boundaries

`main.tsx` mounts `liveRoot.tsx` except explicit build-time demo mode. Live bootstrap fails visibly, retries an unreachable backend, clears session/query state after unauthorized responses/expiry, and never imports fixture fallback. Query reads carry cancellation and no-store transport. Evidence maps distinguish journal records from venue truth, account/control state from process health, declared graph edges from observed flow and protected claims from complete kernel snapshot checks. Protection/heartbeat/account observations age locally independent of successful polling. Missing fields remain unavailable; malformed typed owner read responses are rejected. Chart disposal, visibility/reduced-motion hooks, lazy visual boundaries and the 20-second import bound keep presentation failure isolated from trading.

The locked SDD sections 25.1–25.4 and35.14 explain the retained React/TypeScript/Vite, Query, Radix, Motion and Lightweight Charts stack, ten tabs, exact evidence links and typed owner controls. Browser-only rendering needs no Node production server. The lack of selective3D/Zustand/GSAP/streaming on a particular route is not itself a defect or authorization to introduce dependencies. Fixture data is intentional and isolated; synthetic fixture outcomes are not evidence of readiness. Diagram topology is not IPC health or throughput; unavailable lenses/disabled provider or trading states are not silently filled in. Tracker status never grants runtime/provider/trading authority.

Multiple style files are intentional compatibility consumers: Tracker dynamically mounts `legacy.css?inline`, which imports styles/live/product/m4 and tokens; its cleanup removes the style. Its local SVG is consumed by those styles. The harness imports prior styles too. The modern Glacier/widget layer serves the new routes. Broad stylesheet/component deletion or a theme rewrite would need visual regression evidence and would exceed this bounded review. Existing independent components, historical renderer and helpers remain public test/route contracts; no file removal/merge is justified by disconnection alone.

## Genuine defects corrected

1. `OwnerControls` trusted cached `AVAILABLE` health after a failed refresh because its enablement predicate ignored `health.error`. React Query intentionally retains prior data on refetch failure. Red regression demonstrated enabled Freeze after failed health; adding `!health.error` disables every action until a successful health read. No freshness threshold, new authority, request-id protocol or confirmation mechanism was introduced.
2. Read-only live adapter removed `control` but still exposed `approvalDecision`. A valid Needs You item therefore offered enabled approval buttons even though backend `ReadOnlyBoundary` rejects that POST before handler/gateway. The adapter now omits both optional methods in read-only mode. Existing Needs You capability checks disable buttons. Normal LIVE methods remain present. This was a usability/contract mismatch; server trading authority was already enforced.
3. Shell's LIVE banner asserted `demo venue account (BINANCE_DEMO)` regardless of observed environment. Backend bootstrap publishes actual environment through `glacier_truth.runtime_truth`; `RuntimeTruth.accountLabel` already handles fresh production/demo/testnet/live or unavailable observations. Removed the hardcoded claim; existing runtime labels remain the account source. No environment inference or new account query was added.

4. The live greeting and serious-recovery Needs You link directed the owner to Operations, but Shell dispatches that route to read-only OperationsLog; actual OwnerControls are in the Trades header. Corrected greeting and recovery href to Trades, preserving the same guarded Owner Interface request. No control moved or recovery capability was activated.
